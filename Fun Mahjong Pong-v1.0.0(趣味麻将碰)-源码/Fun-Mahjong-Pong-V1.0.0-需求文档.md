# Fun Mahjong Pong-趣味麻将碰 V1.0.0 需求文档

## 1. 项目概述

### 1.1 项目名称

Fun Mahjong Pong-趣味麻将碰

### 1.2 版本

V1.0.0

### 1.3 产品定位

一款面向移动端的轻休闲麻将消除闯关游戏。玩家通过点击两张相同且可移动的麻将进行配对消除，清空牌面后通关。产品强调轻松、直观、节奏快、视觉精致，适合碎片化娱乐。

### 1.4 目标市场

V1.0.0 面向海外市场，正式环境不展示中文。支持自动语言检测，并覆盖英语、越南语、泰国语、菲律宾语、印度语。

### 1.5 核心体验目标

- 让不认识传统麻将名称的用户，也能通过图案快速识别并完成配对。
- 关卡可无限生成，前期轻松上手，中后期逐步增加复杂度。
- 通过体力、签到、分享、广告补充机会，形成轻量留存循环。
- 通过 Google 账号同步核心进度，保证用户换设备后能继续游玩。

## 2. 核心玩法

### 2.1 基础规则

1. 每局牌面由若干张麻将组成，每种牌必须成对出现。
2. 玩家点击两张图案相同的“自由牌”，即可成功配对并消除。
3. 清空当前关卡全部麻将后，判定为通关。
4. 如果玩家点击不可移动的牌，需要给出明确反馈，提示该牌当前被压住或两侧未开放。
5. 如果当前没有可配对的自由牌，系统可以提示玩家使用“洗牌”，但不应在开局就生成无解或明显卡死的牌面。

### 2.2 自由牌判断

一张麻将可被点击并参与配对，需要同时满足：

- 上方没有其他麻将覆盖。
- 左侧或右侧至少有一侧开放。
- 牌自身仍在当前牌面中，未被消除。

### 2.3 配对成功效果

两张麻将成功配对时，需要有明显的即时反馈：

- 两张牌出现高亮、发光或粒子效果。
- 两张牌向彼此轻微靠拢或弹跳。
- 成功后消失，并更新剩余数量。
- 如果开启音效，播放轻快消除音。
- 如果开启振动，触发轻微震动。

### 2.4 开局发牌动画

每局开始时麻将以动画形式入场：

- 牌从上方、中心或牌桌外侧按层级依次落位。
- 低层先落，高层后落，形成明显堆叠层次。
- 落位时有轻微碰撞、回弹、阴影变化。
- 动画时间需要短，不影响快速开局，建议 0.8-1.5 秒内完成。

## 3. 麻将图案体系

### 3.1 图案总数

V1.0.0 共 34 种牌型：

| 分类 | 数量 | 说明 |
| --- | ---: | --- |
| 筒子 | 9 种 | 1筒至9筒，使用清晰彩色圆点图案 |
| 索子 | 9 种 | 1索至9索，使用清晰彩色竹节/索子图案 |
| 动物 | 8 种 | 使用成年化、精致、非低龄化的动物头像图案 |
| 水果 | 8 种 | 使用成年化、精致、非低龄化的水果图案 |

说明：用户原始描述中出现“9种筒子，9种筒子”，结合当前原型和麻将分类，V1.0.0 按“9种筒子 + 9种索子”执行。

### 3.2 图案设计要求

- 所有图案需要高清、彩色、识别度高。
- 不使用过度低龄化 Emoji 风格。
- 动物和水果不加圆形底色，直接放置在麻将牌面上。
- 图案大小需要充分利用牌面，不应留白过多。
- 同类图案之间需要有明显差异，避免用户误点。
- 筒子、索子、动物、水果都要保持统一的绘制质量和光影质感。

### 3.3 牌型比例

关卡生成时，筒子和索子的出现权重应高于动物和水果。建议整体权重：

- 筒子 + 索子：80%
- 动物 + 水果：20%

该比例用于生成牌型池，不代表每局必须绝对精确，但长期分布需要接近该比例。

## 4. 关卡系统

### 4.1 关卡类型

游戏采用无限关卡设计：

- 第 1 关为教学关。
- 第 2 关起进入正式闯关。
- 关卡可以无限向后生成。
- 用户可游玩当前最高可挑战关，也可以回玩已通关的历史关卡。

### 4.2 第 1 关教学关

第 1 关尽量简单：

- 不使用两层堆叠。
- 牌量少，建议 6-10 张。
- 只展示 3-5 种牌型。
- 通过新手引导说明：
  - 找到相同牌。
  - 只选择自由牌。
  - 清空牌面即可通关。

### 4.3 关卡命名

关卡统一显示为：

- 第 1 关
- 第 2 关
- 第 3 关

不附加“春水”“竹影”等副标题。

### 4.4 无限关卡生成逻辑

关卡不需要手工配置到无限数量，而是通过算法生成。

每关生成时需要决定：

- 总牌数。
- 牌型数量。
- 堆叠层数。
- 牌面布局。
- 可解性。

### 4.5 推荐牌数增长规则

牌数必须为偶数。随着关卡数提升，牌数逐步增加，但不能无限堆到屏幕外。建议采用分段增长：

| 关卡范围 | 推荐总牌数 | 推荐层数 | 设计目标 |
| --- | ---: | ---: | --- |
| 第 1 关 | 6-10 | 1 | 教学，极简 |
| 第 2-5 关 | 12-20 | 1-2 | 熟悉规则 |
| 第 6-15 关 | 22-34 | 2-3 | 引入遮挡 |
| 第 16-30 关 | 36-48 | 3-4 | 提升思考量 |
| 第 31-50 关 | 50-64 | 4-5 | 中等挑战 |
| 第 51-100 关 | 66-84 | 5-6 | 强化空间规划 |
| 第 101-200 关 | 86-108 | 6-7 | 高密度布局 |
| 第 201-500 关 | 110-132 | 7-8 | 高级挑战 |
| 第 501 关以后 | 132-160 | 8-10 | 保持难度上限，变化布局 |

说明：

- 牌数不建议无上限增长，否则移动端屏幕无法承载。
- 高关卡主要通过布局复杂度、层数、可移动牌比例和牌型数量增加难度，而不是单纯增加牌数。
- 第 501 关后建议牌数进入软上限，主要变化堆叠形状和解题路径。

### 4.6 推荐牌数公式

开发可以使用如下思路：

```text
if level == 1:
  totalTiles = 8
else:
  base = 12 + floor(level * 1.8)
  totalTiles = clampToEven(base, min=12, max=160)
```

为了避免第 40 关和第 50 关牌数相同，应加入分段或曲线增长。也可以按关卡区间配置牌数上限，每 5-10 关增加一次。

### 4.7 牌型数量规则

每关牌型数量需要跟随总牌数变化：

```text
pairCount = totalTiles / 2
typeCount = clamp(round(pairCount * 0.65), min=3, max=34)
```

示例：

- 14 张牌：7 对，建议 6-7 种牌型。
- 60 张牌：30 对，建议 20-26 种牌型。
- 100 张牌：50 对，建议 28-34 种牌型。

### 4.8 高关卡堆叠设计

高关卡不能简单把牌堆满导致溢出屏幕，需要采用“自适应布局 + 层级压缩 + 区域分组”。

设计原则：

1. 牌桌区域需要占据顶部统计区和底部按钮之间的大部分空间。
2. 除第 1 关外，牌面应尽量铺满可用区域。
3. 麻将尺寸自适应，不能超出屏幕边界。
4. 单张麻将必须保持固定宽高比例，不能拉伸变形。
5. 牌最小尺寸不低于当前高关卡可识别尺寸。
6. 当牌数增加时，优先增加层数和布局密度，而不是让牌溢出。
7. 高层牌要有明确的立体高度，用户能看出哪些牌被压住。

### 4.9 推荐布局算法

每关生成可使用以下流程：

1. 根据关卡号计算总牌数、层数、牌型数量。
2. 根据设备可用区域计算最大可容纳行列。
3. 根据总牌数选择布局模板：
   - 小关卡：中心散布。
   - 中关卡：矩形、菱形、阶梯、环形。
   - 高关卡：多层塔形、错位矩阵、分区堆叠。
4. 每一层相对下一层产生少量偏移，形成压牌关系。
5. 生成时保证每张上层牌覆盖下层牌的逻辑可被判断。
6. 生成完成后运行可解性校验。
7. 如果无解，自动重排或重新生成。

### 4.10 可解性要求

每关必须保证理论可解。推荐策略：

- 先生成一个可消除顺序。
- 按反向顺序把牌放回牌面。
- 确保每一步至少存在一组可配对自由牌。
- 如果玩家过程中导致无可配对牌，可以允许洗牌，但初始牌面必须可解。

## 5. 体力系统

### 5.1 基础规则

- 用户默认起步拥有 5 点体力。
- 每次闯关消耗 1 点体力。
- 重新玩历史关卡也消耗 1 点体力。
- 体力为 0 时，用户仍可点击闯关按钮，但需要弹出体力不足提示，引导看广告或分享获得体力。

### 5.2 每日恢复

按照用户设备所在地区的自然日 0 点刷新。

恢复规则：

- 如果当前体力少于 5 点，第二天补满到 5 点。
- 如果当前体力等于 5 点，不变化。
- 如果当前体力超过 5 点，不清零、不削减，继续保留。

示例：

| 前一天结束体力 | 第二天打开后体力 |
| ---: | ---: |
| 0 | 5 |
| 2 | 5 |
| 5 | 5 |
| 8 | 8 |

### 5.3 广告获得体力

- 用户可主动点击体力旁边的加号。
- 成功看完广告后增加 1 点体力。
- 体力没有上限。
- 如果广告加载失败，需要给出提示。

### 5.4 分享获得体力

- 分享次数不限制。
- 每天第一次成功分享获得 2 点体力。
- 当天第二次及之后分享不再获得体力，但仍允许继续分享。
- 分享弹窗中不展示“每天第一次分享获得2点体力。”这一字段。

### 5.5 签到获得体力

每周签到奖励：

| 星期 | 奖励 |
| --- | ---: |
| 周一 | +1 体力 |
| 周二 | +1 体力 |
| 周三 | +1 体力 |
| 周四 | +1 体力 |
| 周五 | +1 体力 |
| 周六 | +2 体力 |
| 周日 | +2 体力 |

规则：

- 用户每天第一次打开 App，如果当天未签到，展示签到弹窗。
- 用户也可从首页签到入口主动打开签到弹窗。
- 已签到状态需要在首页显示。
- 签到奖励领取后立即增加体力。

## 6. 星级系统

### 6.1 星级标准

每关最高 3 星，最低 0 星。

星级只与本局是否使用提示或洗牌有关：

- 不使用提示、不使用洗牌：3 星。
- 使用提示或洗牌任意 1 次：2 星。
- 使用提示或洗牌累计 2 次：1 星。
- 使用提示或洗牌累计 3 次及以上：0 星。

公式：

```text
stars = max(0, 3 - hintUsedCount - shuffleUsedCount)
```

### 6.2 星级展示

- 已获得星星显示为金色。
- 未获得星星显示为灰色。
- 通关弹窗中三颗星应有明显层次感，3 星状态视觉最强。
- 历史关卡展示该关已获得的最高星数。

### 6.3 星级保存

每关只保存历史最高星数。

示例：

- 第 5 关首次通关获得 2 星。
- 后续重玩第 5 关获得 3 星，则更新为 3 星。
- 后续再次重玩获得 1 星，不覆盖原来的 3 星。

## 7. 提示与洗牌

### 7.1 每关次数

每关默认：

- 提示：2 次。
- 洗牌：2 次。

### 7.2 次数消耗

- 点击提示后消耗 1 次提示机会。
- 点击洗牌后消耗 1 次洗牌机会。
- 每使用 1 次提示或洗牌，通关星级减少 1 星，最低 0 星。

### 7.3 用完后的广告逻辑

当提示或洗牌次数用完：

- 按钮不置灰。
- 右上角角标从剩余次数改为视频图标。
- 用户点击后触发看广告流程。
- 成功看完广告后增加对应功能 1 次使用机会，随后可以继续使用。

### 7.4 提示效果

点击提示时：

- 系统找到当前可配对的一组牌。
- 两张麻将需要出现明显彩虹色高亮。
- 高亮持续一小段时间，建议 1.2-2 秒。
- 如果当前没有可配对牌，提示用户需要洗牌。

### 7.5 洗牌效果

点击洗牌时：

- 仅重排当前未消除的麻将。
- 不改变剩余牌型和牌的数量。
- 洗牌后必须保证存在至少一组可配对牌。
- 洗牌动画要明显，但不能过长。

## 8. 账号与进度同步

### 8.1 登录方式

V1.0.0 支持 Google 账号登录，用于保存核心进度。

### 8.2 同步范围

只同步：

- 最高关卡。
- 每关最高星数。

不参与云同步，仅保存在当前设备：

- 体力。
- 签到记录。
- 分享奖励记录。
- 音效、振动、语言等设置。
- 当日广告观看状态。

产品内需要明确提示：

“仅同步最高关卡和每关最高星数。体力、签到、分享奖励及设置仅保存在当前设备。”

### 8.3 本地与账号进度合并逻辑

登录 Google 账号后，需要合并本地进度和云端账号进度，取更高值。

#### 情况 A：本地有记录，账号没记录

处理方式：

- 将本地最高关卡上传到账号。
- 将本地每关最高星数上传到账号。
- 登录后用户进度不倒退。

示例：

- 本地最高第 30 关。
- 账号无数据。
- 登录后账号最高关卡变为第 30 关。

#### 情况 B：本地没记录，账号有记录

处理方式：

- 下载账号最高关卡到本地。
- 下载账号每关最高星数到本地。
- 用户可继续账号上的进度。

示例：

- 本地最高第 1 关。
- 账号最高第 80 关。
- 登录后本地最高关卡变为第 80 关。

#### 情况 C：本地和账号都有记录

处理方式：

- 最高关卡取两边最大值。
- 每一关星数逐关取最大值。
- 合并后的结果同时写入本地和账号。

示例：

```text
本地最高关卡：50
账号最高关卡：80
合并后最高关卡：80

本地第 10 关：3 星
账号第 10 关：2 星
合并后第 10 关：3 星

本地第 20 关：1 星
账号第 20 关：3 星
合并后第 20 关：3 星
```

### 8.4 退出登录

用户点击退出 Google 账号时，需要二次确认。

弹窗文案建议：

- 标题：退出 Google 账号？
- 说明：退出后，本设备仍保留当前本地进度；后续新进度不会同步到 Google 账号。
- 按钮：取消、确认退出。

退出后：

- 本地进度保留。
- 云端数据不删除。
- 用户再次登录同一账号时，继续执行本地与账号取最高值的合并逻辑。

## 9. 多语言

### 9.1 支持语言

正式环境支持：

- 自动检测。
- 英语。
- 越南语。
- 泰国语。
- 菲律宾语。
- 印度语。

如果没有检测到上述语言，默认使用英语。

### 9.2 中文限制

正式环境不能出现中文。

说明：

- 当前原型可以保留中文用于评审。
- 上线构建必须切换为多语言文案。
- 简体中文仅作为内部调试语言，不进入正式环境。

### 9.3 自动检测逻辑

首次打开 App：

1. 读取系统语言。
2. 如果系统语言属于支持语言，则使用对应语言。
3. 如果不属于支持语言，则使用英语。
4. 用户可在设置中手动切换语言。
5. 用户手动切换后，优先使用用户选择，不再自动覆盖。

## 10. 头像系统

### 10.1 初始头像

用户初始拥有 3 个可用头像。

### 10.2 解锁规则

之后每 50 关解锁 1 个新头像。

当前暂定支持到 1000 关头像：

| 最高通关关卡 | 解锁情况 |
| ---: | --- |
| 初始 | 3 个头像 |
| 50 | 解锁第 4 个头像 |
| 100 | 解锁第 5 个头像 |
| 150 | 解锁第 6 个头像 |
| ... | 每 50 关解锁 1 个 |
| 1000 | 解锁到当前规划的最高头像 |

1000 关之后的头像后续版本再扩展。

### 10.3 个人信息弹窗

点击首页当前关卡附近的用户头像，打开个人信息弹窗。

弹窗内容：

- 当前头像。
- 玩家名字。
- 修改名字入口。
- 最高关卡。
- 头像列表。
- 头像解锁条件。
- 保存按钮。

名字规则：

- 最多 15 个字符。
- 不能为空。
- 超过字符限制时给出提示。

头像状态：

- 已解锁：可点击选择。
- 当前使用：显示选中状态。
- 未解锁：显示锁标识和解锁条件。

## 11. 页面与交互

### 11.1 首页 / 关卡地图

首页采用纵向关卡地图形式，玩家可看到当前关卡和已通关关卡。

核心元素：

- 游戏 Logo。
- 签到入口。
- 体力区域。
- 分享按钮。
- 设置按钮。
- 关卡路径。
- 当前玩家头像。
- 底部挑战按钮。
- 玩法入口。

交互要求：

1. 用户可以上下滑动地图查看已通关关卡。
2. 已通关关卡可点击重玩。
3. 未解锁关卡不可进入。
4. 当前可挑战关卡突出展示。
5. 当前玩家头像堆叠在对应关卡卡片右上角，作为当前位置标识。
6. 点击底部“挑战第 X 关”消耗 1 点体力并进入游戏。
7. 体力不足时弹出体力不足弹窗，引导看广告或分享。

### 11.2 游戏页

游戏页为全屏牌桌，不使用生硬卡片容器。

核心元素：

- 左上角体力。
- 顶部关卡标题。
- 右上角设置按钮。
- 顶部统计区域：总数、种类、剩余。
- 中间麻将牌桌。
- 底部提示按钮。
- 底部洗牌按钮。

统计说明：

- 总数：本局开始时的麻将总数，不随消除变化。
- 种类：本局牌型数量，不随消除变化。
- 剩余：当前剩余麻将数量，随消除实时变化。

交互要求：

1. 点击自由牌后进入选中状态。
2. 点击第二张相同自由牌后成功消除。
3. 点击不同牌时，切换或取消选中，具体以手感顺畅为准。
4. 点击不可移动牌时，需要提示该牌被压住或暂不可选。
5. 点击设置按钮打开游戏设置弹窗。
6. 点击提示或洗牌时按对应规则消耗次数和星级。

### 11.3 完成弹窗

通关后展示居中完成弹窗，而不是整页完成页。

弹窗内容：

- 通关标题。
- 星级结果。
- 简短鼓励文案。
- 下一关按钮。
- 再玩一次按钮。
- 返回主页入口。

交互要求：

- “下一关”按钮文案居中。
- 点击下一关需要提示或标明会消耗 1 点体力。
- 点击再玩一次也需要提示或标明会消耗 1 点体力。
- 如果体力不足，点击后进入体力不足引导。
- 星级需要有明显层次感，3 星视觉最强。

### 11.4 首页设置弹窗

设置内容：

- 音效开关。
- 振动开关。
- 语言入口。
- 保持进度 / Google 账号登录状态。
- 关于入口。
- 退出 Google 账号入口。
- 同步说明。

交互要求：

- 点击“关于”时，关闭设置弹窗，只展示关于弹窗。
- 点击退出 Google 账号时，展示二次确认。
- 未登录时显示 Google 登录 / 保持进度入口。
- 已登录时显示已同步状态和退出入口。

### 11.5 游戏设置弹窗

游戏内设置内容：

- 音效开关。
- 振动开关。
- 重新开始。
- 返回首页。

交互要求：

- 重新开始当前关也消耗 1 点体力。
- 返回首页不消耗体力。
- 点击重新开始前如有必要可二次确认，避免误触。

### 11.6 签到弹窗

签到弹窗展示一周奖励。

内容：

- 当天高亮。

- 未到日期显示未领取状态。
- 今日可签到时显示“签到领取体力”按钮。
- 今日已签到时显示“今日已签到”按钮或不可点击状态。

交互要求：

- 每天第一次打开 App 且未签到时自动弹出。
- 用户点击签到后立即增加体力。
- 首页签到入口需要根据状态显示“未签到”或“已签到”。

### 11.7 分享弹窗

分享弹窗从底部弹出。

内容：

- 非当天第一次分享，仅完成分享，不增加体力。

3. 清空即通关：遇到困难可使用提示或洗牌。

## 12. 数据存储

### 12.1 本地存储

本地需要保存：

- 当前最高关卡。
- 每关最高星数。
- 当前体力。
- 上次体力刷新日期。
- 本周签到记录。
- 今日是否已分享领取奖励。
- 设置项：音效、振动、语言。
- 用户名。
- 当前头像。
- 已解锁头像。

### 12.2 云端存储

Google 账号只保存：

- 最高关卡。
- 每关最高星数。

不保存：

- 体力。
- 签到。
- 分享奖励。
- 广告状态。
- 音效、振动、语言等本机设置。

### 12.3 进度不会倒退

任何同步、重玩、退出登录、重新登录，都不能导致用户最高关卡或每关最高星数倒退。

## 13. 广告入口

V1.0.0 广告只用于奖励，不做强制插屏。

奖励广告入口：

- 体力不足时看广告 +1 体力。
- 用户主动点击体力加号看广告 +1 体力。
- 提示次数用完后看广告 +1 次提示。
- 洗牌次数用完后看广告 +1 次洗牌。

广告失败处理：

- 广告加载失败：提示“广告暂时不可用，请稍后再试”。
- 用户中途退出广告：不发放奖励。
- 广告成功看完：立即发放奖励。

## 14. 关键状态流

### 14.1 进入关卡

```text
用户点击关卡或挑战按钮
→ 检查关卡是否已解锁
→ 检查体力是否大于 0
→ 体力 -1
→ 生成关卡
→ 播放发牌动画
→ 开始游戏
```

### 14.2 通关

```text
剩余牌数 = 0
→ 计算星数
→ 更新本地该关最高星数
→ 如果是最高关卡，解锁下一关
→ 如果已登录 Google，上传最高值进度
→ 展示完成弹窗
```

### 14.3 登录同步

```text
用户点击 Google 登录
→ 登录成功
→ 读取本地最高关卡和每关星数
→ 读取云端最高关卡和每关星数
→ 逐项取最高值
→ 写回本地
→ 写回云端
→ 展示同步成功
```

### 14.4 每日打开 App

```text
打开 App
→ 检查地区日期是否变化
→ 如果体力少于 5，补到 5
→ 重置今日分享奖励状态
→ 检查今日是否签到
→ 未签到则展示签到弹窗
```

## 15. 非功能要求

### 15.1 性能

- 移动端首屏加载需要尽可能快。
- 发牌动画和消除动画不能明显卡顿。
- 高关卡大量牌堆叠时仍需保持可点击和流畅。

### 15.2 适配

- 优先适配主流手机竖屏。
- 需要兼容不同高度屏幕，避免顶部信息或底部按钮遮挡牌面。
- 麻将尺寸按可用空间自适应，不能溢出屏幕。

### 15.3 可访问性

- 图案之间需要足够清晰，避免仅靠颜色区分。
- 关键按钮需要足够大，适合手指点击。
- 重要提示需要清楚，不依赖音效。

### 15.4 容错

- 本地存储异常时，不能导致游戏无法进入。
- 云同步失败时，本地进度仍可继续。
- 广告失败时，不扣除用户已有资源。

## 16. V1.0.0 暂不包含

- 付费内购。
- 强制广告。
- 好友实时排行榜。
- 多人对战。
- 复杂任务系统。
- 1000 关之后的新头像设计。

## 17. 开发验收标准

### 17.1 玩法验收

- 玩家能完成配对、消除、通关。
- 被压住的牌不能被误判为可点击。
- 初始牌面必须可解。
- 高关卡不出现麻将溢出屏幕。

### 17.2 体力验收

- 闯关和重玩都会扣 1 点体力。
- 少于 5 点体力时，第二天恢复到 5。
- 超过 5 点体力时，第二天保留超出值。
- 签到、广告、分享能正确增加体力。

### 17.3 星级验收

- 不用提示和洗牌通关为 3 星。
- 使用一次降到 2 星。
- 使用两次降到 1 星。
- 使用三次及以上为 0 星。
- 历史关卡只保存最高星数。

### 17.4 同步验收

- 本地有进度、账号无进度时，上传本地进度。
- 本地无进度、账号有进度时，下载账号进度。
- 两边都有进度时，最高关卡和每关星数逐项取最大值。
- 体力、签到、分享奖励和设置不参与同步。
- 退出登录有二次确认。

### 17.5 多语言验收

- 支持自动检测。
- 支持英语、越南语、泰国语、菲律宾语、印度语。
- 未命中语言默认英语。
- 正式环境不出现中文。
