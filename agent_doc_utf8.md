根据会话二(2026-09-16)的完整操作记录,Agent 是通过 miniprogram-automator 这个官方微信小程序自动化库,配合 DevTools 自带的 CLI 来实现远程控制和截图的。完整方法如下:

一、前提准备

1. 定位 DevTools 安装路径和 CLI 工具
CLI="C:/Program Files (x86)/Tencent/微信web开发者工具/cli.bat"

2. 必须打开 DevTools 的"安全设置"
在微信开发者工具的 设置 → 安全设置 中,需要开启 "服务端口"(CLI/自动化端口) 开关,否则 automator 无法连接。这是 agent 踩过的坑之一(第一次直接连接失败)。

3. 安装依赖
npm install --save-dev miniprogram-automator

二、两种启动方式

Agent 一开始尝试 automator.launch() 直接拉起 IDE,但因为 DevTools 装在非默认路径,自动查找失败。最终采用的可靠方案是"手动开端口 + 脚本连接"两步走:

第一步:命令行把 DevTools 启动为自动化模式,开放端口
cd "/c/Program Files (x86)/Tencent/微信web开发者工具"
./cli.bat auto --project "C:/mydev/majiang/majiang-mp/dist/build/mp-weixin" --auto-port 9420
每次改完代码、npm run build:mp-weixin 重新编译后,还需要先 ./cli.bat quit 关掉旧实例再重新 auto 启动,才能加载最新代码。也用 netstat -ano | grep ":9420.*LISTENING" 轮询确认端口真的起来了。

第二步:Node 脚本里连接已运行的实例
const automator = require('miniprogram-automator');
const mp = await automator.connect({
  wsEndpoint: 'ws://127.0.0.1:9420',
  timeout: 120000
});

四、截图核心示例(即 test/mp-shot.cjs)

const automator = require('miniprogram-automator');
const path = require('path');
const OUT = path.resolve(__dirname, '../mp-screenshot.png');

(async () => {
  const mp = await automator.connect({ wsEndpoint: 'ws://127.0.0.1:9420', timeout: 120000 });
  const page = await mp.currentPage();
  await new Promise(r => setTimeout(r, 8000)); // 等动画/渲染稳定
  await mp.screenshot({ path: OUT });
  console.log('screenshot ->', OUT);
  await mp.disconnect();
})().catch(e => { console.error('FAILED:', e.message); process.exit(1); });
截图存到本地 png 后,agent 再用 Read 工具直接读取图片文件,以视觉方式核对 UI 是否与参考图一致。

五、稳定性技巧

- 用 for i in 1..N; do node xxx.cjs && break; sleep N; done 的重试循环,应对 DevTools 启动/编译尚未就绪导致的连接失败。
- 每次改动 UI 相关代码后固定套路:改代码 → npm run build:mp-weixin → cli.bat quit → cli.bat auto --auto-port 9420 → 等端口 → 跑对应的 .cjs 探测/截图脚本。
